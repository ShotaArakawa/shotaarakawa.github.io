インボイス請求書メーカー(invoice-maker)

概要

フリーランス・個人事業主向けに、インボイス制度(適格請求書等保存方式)に対応した請求書・見積書をブラウザだけで作成し、PDF で出力できるツール。 データは端末のブラウザ(localStorage)に保存するため、登録不要・サーバー費用ほぼゼロで提供できる。

想定ユーザー

  • 個人で仕事を受けるフリーランス(デザイナー、エンジニア、ライター、カメラマン、講師など)
  • 月に数件〜数十件の請求書を出す小規模事業者
  • 会計ソフトの請求書機能は「高い・重い」と感じている人、Excel テンプレからの乗り換え層

MVP の機能

雛形で動くもの(✅)と未実装(⬜)

  • ✅ 請求書 / 見積書の作成フォーム(番号・発行日・支払期限/有効期限・件名・取引先・明細・備考)
  • ✅ インボイスの記載事項: 登録番号、税率ごとの対象額と消費税額、軽減税率対象(※)の明示
  • ✅ 端数処理は「税率ごとに合計してから 1 回切り捨て」(インボイス制度のルール)
  • ✅ 単価の税抜 / 税込の切り替え
  • ✅ 源泉徴収税の差し引き(100 万円以下 10.21%、超過分 20.42%)
  • ✅ A4 プレビュー、PDF 出力(ブラウザの印刷 →「PDF に保存」)
  • ✅ 取引先・品目のマスタ保存と、フォームへの呼び出し
  • ✅ 書類の保存・履歴・複製・削除、見積書 → 請求書への変換
  • ✅ 登録番号の形式チェック(T + 13 桁)
  • ⬜ PDF ファイルの直接生成(ボタン 1 つでダウンロード)
  • ⬜ 印影・ロゴ画像
  • ⬜ クラウド保存・複数端末同期(有料)
  • ⬜ テンプレートの切り替え(有料)

技術構成

  • Vite 6 + React 18 + TypeScript(静的サイト。Cloudflare Pages に dist/ を置くだけで公開できる想定)
  • 保存: src/lib/storage.ts の DataStore インターフェース。雛形は localStorage 実装、クラウド保存は Supabase 実装に差し替える
  • 計算ロジック: src/lib/calc.ts(UI から独立。npm test で Node 標準のテストランナーで検証)
src/
  App.tsx                    タブ切り替え・保存などの状態管理
  components/
    DocumentEditor.tsx       入力フォーム
    DocumentPreview.tsx      A4 プレビュー(印刷対象)
    HistoryPanel.tsx         保存済み書類の一覧
    MasterPanel.tsx          取引先・品目マスタ
    IssuerPanel.tsx          自社情報(登録番号・振込先)
  lib/
    calc.ts / calc.test.ts   税額・源泉徴収の計算とテスト
    storage.ts               DataStore・採番・サンプルデータ
    format.ts                金額・日付の整形

使い方(開発)

npm install
npm run dev      # 開発サーバー
npm run build    # 型チェック + 本番ビルド
npm test         # 計算ロジックのテスト(Node 22.6 以降 / 型ストリップを使用)

収益化案

  • 無料: 作成・PDF 出力・ローカル保存は無制限(集客の入口)
  • 有料(月 300〜500 円程度): 履歴のクラウド保存と複数端末同期、追加テンプレート、ロゴ・印影の差し込み、透かし(「Created with ...」フッター)の非表示
  • 将来: 請求書のメール送付・入金ステータス管理、CSV エクスポート(会計ソフト取り込み用)

集客案

  • SEO: 「インボイス 請求書 テンプレート 無料」「請求書 源泉徴収 計算」「軽減税率 請求書 書き方」など、制度に関する解説記事 + ツール導線
  • 職種別のサンプル(デザイナー用、エンジニア用、講師用)ページを用意してロングテールを取る
  • X / note でフリーランス向けに「登録不要・ブラウザ完結」を訴求
  • 無料版の PDF フッターに小さくサービス名を入れて口コミ流入

次にやること

  1. PDF の直接生成(日本語フォントの埋め込みが必要。サイズとライセンスを確認して pdf-lib 等を検討)
  2. 印刷時の改ページ対応(明細が多いと 2 ページ目に入る時の見出し繰り返し)
  3. ロゴ・印影画像のアップロード(ブラウザ内で保持)
  4. データのエクスポート / インポート(JSON)で端末移行・バックアップ
  5. 登録番号の実在確認(国税庁の適格請求書発行事業者公表 API。アプリ ID 取得が必要なので後回し)
  6. Supabase でクラウド保存(Auth + RLS)と有料プラン判定
  7. Cloudflare Pages へのデプロイ設定

注意

  • 税額計算は一般的なルールに沿った実装だが、税務上の判断が必要なケース(源泉徴収の対象可否など)はユーザーの責任で確認してもらう旨を、公開前に画面上で明記すること
